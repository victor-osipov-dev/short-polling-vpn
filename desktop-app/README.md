# Short Polling VPN (Desktop)

Новый десктопный клиент Short Polling VPN: Electron + React + Vite + Tailwind, headless-бэкенд на Python и TUN-режим через sing-box.

## Возможности

- Загрузка подписки по URL и список профилей с группировкой по exit-стране, поиском и фильтрами.
- Применение split-маршрутизации профиля (`ru` / `non_ru` / `private`) из подписки.
- Два режима:
  - **Системный прокси Windows** — HTTP-прокси `127.0.0.1:8891`. Прежние настройки Windows сохраняются и восстанавливаются при отключении.
  - **VPN TUN** — sing-box поднимает адаптер `custom-tun`, SOCKS5-аутбаунд `127.0.0.1:8890` уходит в наш короткополлинговый туннель. Требуются права администратора.
- Статус, внешний IP, аптайм, счётчики трафика и живой журнал событий.
- Смена профиля/режима/global-режима на ходу: бэкенд корректно останавливает старую сессию и поднимает новую.

## Запуск готовой сборки

Готовая portable-сборка: `release/Short-Polling-VPN-1.0.0-portable.exe`.

Для удобства используйте `run-short-polling-vpn.bat` — он найдёт актуальный portable-файл в `release/` и запустит его. Скрипт `scripts/create-shortcuts.ps1` создаст на рабочем столе два ярлыка: обычный и «(Admin)» — второй сразу запрашивает права для TUN-режима.

Для TUN-режима запустите приложение от имени администратора (правой кнопкой → «Запуск от имени администратора» или кнопка в разделе «Подписка»).

## Структура

```

  electron/main.cjs          Главный процесс: жизненный цикл, IPC, запуск бэкенда
  electron/preload.cjs       contextBridge API для рендерера
  src/                       React UI
  backend/vpn_backend.py     JSON API, туннель, прокси, sing-box supervisor

  resources/sing-box/        Бандл sing-box 1.14.3
  assets/icon.ico            Иконка приложения

```

Бэкенд переиспользует ядро из корня репозитория: `tunnel.py`, `socks5_server.py`, `desktop_client.py` (HTTP CONNECT), `subscription.py`, `split_routing.py`.

## Разработка

```bat
npm install
npm run dev
```

`npm run dev` поднимает Vite на `127.0.0.1:5173`, затем Electron. Electron сам выбирает свободный порт для локального API и запускает бэкенд.

## Сборка релиза

```bat
scripts\fetch-singbox.ps1
scripts\build-backend.bat
npm run dist
```

`electron-builder` соберёт portable `.exe` в `release/`. Готовый релиз собирается одним скриптом `scripts\release.bat` (бэкенд + portable + ярлыки). Публикация на GitHub: `scripts\publish-release.ps1` (нужен сохранённый git-токен; скрипт сам создаст тег `v1.0.0`, релиз и загрузит `.exe`). В состав входят React-бандл, бэкенд (`vpn-backend.exe`), ядро `.py` и `sing-box`. Бинарники не хранятся в git, поэтому на чистом клоне сначала выполните `scripts\fetch-singbox.ps1`.

## Права администратора и TUN

TUN создаёт сетевой адаптер и меняет таблицу маршрутов. В обычном режиме кнопка TUN показывает предупреждение; используйте «Перезапустить от администратора». sing-box проверяется командой `sing-box check` перед запуском; конфиг сохраняется в `%LOCALAPPDATA%\ShortPollingVPN\sing-box-tun.json` и удаляется при отключении. Настройки переносятся из старой папки `%LOCALAPPDATA%\FimdiVPN`.

При включении TUN:
- системный прокси временно отключается (иначе сторонний прокси, например v2rayN, перехватывает трафик и «интернет пропадает»); после отключения настройки восстанавливаются;
- UDP/QUIC отклоняется, потому что локальный SOCKS5 умеет только TCP CONNECT — приложения переключаются на TCP;
- маршруты к узлам подписки и локальный DNS идут мимо TUN, чтобы опрос сервера не зацикливался.

Чтобы polling-запросы не попадали в собственный TUN, в конфиг добавлены:
- `route_exclude_address` с IP узлов подписки и локальными DNS;
- правило `process_name` → `direct` для `python.exe` / `vpn-backend.exe`, а также для процессов из `directProcesses` в `settings.json` (по умолчанию `OpenCode.exe`, `opencode-cli.exe`). Приложения из этого списка идут мимо туннеля — это лечит обрывы длинных потоковых соединений (например, ответов ИИ-клиентов).

## Задержка и опрос

Клиент опрашивает сервер адаптивно: при открытых соединениях и активности раз в `poll_interval_ms` (по умолчанию 100 мс), в простое (нет сессий) — раз в `poll_idle_ms` (800 мс), но никогда чаще `poll_min_ms` (100 мс — щадит CDN). Новый трафик будит цикл опроса сразу, а `poll_coalesce_ms` склеивает открытие сессии с первыми данными, экономя round-trip на подключении. Выбор узла — `fastest`: новое подключение идёт на URL с наименьшим измеренным RTT.

DNS-режим задаётся в `settings.json` ключом `dnsMode`:
- `tunnel` (по умолчанию) — DoH через туннель, приватно, но каждый запрос стоит полл-round-trip;
- `direct` — DoH напрямую (зашифровано, быстрее);
- `local` — системный DNS (самый быстрый, но провайдер видит имена).

## Порты

| Порт | Назначение |
| ---- | ---------- |
| 8890 | Локальный SOCKS5 (upstream для sing-box и прокси-режима) |
| 8891 | Локальный HTTP-прокси (CONNECT + обычные HTTP-запросы) |
| динамический | Управляющий JSON API бэкенда (только loopback, только Electron) |

## Подписка

Формат тот же, что у остальных клиентов проекта. Для профилей из `client_profiles` бэкенд переводит `route_ru` / `route_non_ru` / `route_private` в `split_routing.actions`. Пустая строка или `direct` означает прямой выход. Тумблер «Весь трафик» подменяет `ru` и `non_ru` на exit-маршрут профиля, приватные сети остаются прямыми.

Если в подписке нет `client_profiles`, каждый узел становится отдельным профилем «весь трафик через узел».

## Важные замечания

- В проектном списке RU-доменов (`fimdi.ru/rules/ru-domains.txt`) есть, например, `ipinfo.io` и `x.com`; для проверки внешнего IP используется `cloudflare.com/cdn-cgi/trace`, которого там нет. Сайты из RU-списка идут напрямую по дизайну split-routing.
- Не трогать второй xray/x-ui на `ru-2`.
- Push в GitHub — только по явной просьбе.
