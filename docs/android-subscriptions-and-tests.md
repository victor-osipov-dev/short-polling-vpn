# Android: несколько подписок и проверка подключения

## Несколько подписок

Раньше профили всех подписок имели id вида `sub:<client_profile_id>`.
Админ-панель раздаёт один и тот же каталог именованных профилей во все
подписки, поэтому id совпадали: импорт второй подписки перезаписывал
профили первой (визуально «старая подписка удалилась»).

Теперь:

- id профиля = `sub:<slug>:<client_profile_id>`, где `slug` — стабильный
  хеш URL подписки;
- `device_id` генерируется отдельно для каждой подписки;
- повторный импорт обновляет только профили этой подписки и удаляет лишь
  те, которые исчезли из свежего payload;
- старые профили (`sub:<client_profile_id>`) узнаются по паре
  «URL подписки + имя профиля» и переиспользуют свой id, поэтому дубликаты
  не появляются;
- на главном экране профили сгруппированы по подписке. В заголовке группы:
  «Тест всех», обновление подписки и удаление только этой подписки.

Профили, потерянные старой версией приложения, автоматически не
восстанавливаются — такую подписку нужно добавить заново.

## Проверка подключения

Кнопка «Тест» у профиля и «Тест всех» у подписки проверяют реальное
подключение, а не ICMP:

1. Python-движок поднимает временный туннель с настройками профиля
   (маршруты берутся из снимка `nodes`/`routes`, без повторной загрузки
   подписки).
2. Через выбранный маршрут открывается сессия к `api.ipify.org:80`
   (fallback `ifconfig.me:80`).
3. UI показывает задержку до первого байта, exit IP и фактическую цепочку
   узлов, например `fi-1 → de-1`.

Если маршрут невозможен (нет доступных узлов, битая цепочка), тест
показывает ошибку маршрутизации, а не молчаливое переключение на другой
узел. Проверка работает и без запущенного VPN; тесты выполняются
последовательно, чтобы не конкурировать за сеть и CPU.
